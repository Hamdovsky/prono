# تقرير حول مشروع Titanium Promosport AI - Stitch System

## 1. مقدمة

يهدف مشروع **Titanium Promosport AI - Stitch System** إلى بناء منصة ذكية لتحليل المباريات الرياضية وتوليد توقعات مبنية على البيانات، خاصة في مجال مسابقات Promosport وأسواق الرهانات الرياضية المشابهة. يعتمد المشروع على جمع البيانات من مصادر رياضية مختلفة، معالجتها، تحليلها بواسطة خوارزميات تعلم آلي، ثم عرض النتائج للمستخدم عبر واجهة ويب تفاعلية.

يجمع هذا المشروع بين تطوير الويب، قواعد البيانات، الذكاء الاصطناعي، أنظمة التخزين المؤقت، المراقبة، والأتمتة. لذلك فهو ليس مجرد تطبيق واجهة أمامية، بل نظام متكامل يحتوي على عدة طبقات تعمل معا لتقديم توقعات سريعة ومنظمة وقابلة للتحديث في الوقت الحقيقي.

## 2. أهداف المشروع

تتمثل الأهداف الأساسية للمشروع في:

- جمع بيانات المباريات والبطولات من مصادر خارجية مثل Sofascore وPromosport.
- تحليل المعطيات الرياضية مثل النتائج السابقة، مستوى الفرق، المواجهات المباشرة، الإصابات، الحالة الفنية، وتحركات السوق.
- توليد توقعات ذكية باستعمال نماذج تعلم آلي مثل XGBoost ونماذج هجينة أخرى.
- عرض التوقعات في واجهة مستخدم واضحة وتفاعلية.
- توفير تحديثات فورية باستعمال WebSocket وSocket.IO.
- تحسين الأداء عبر التخزين المؤقت باستخدام Redis أو ذاكرة داخلية بديلة.
- مراقبة حالة النظام، الأخطاء، الأداء، وسلامة الخدمات.
- دعم التشغيل المحلي، الإنتاجي، والحاويات باستخدام Docker.

## 3. التقنيات المستعملة

يعتمد المشروع على مجموعة واسعة من التقنيات الحديثة:

| المجال | التقنيات |
|---|---|
| الواجهة الأمامية | React, Vite, CSS, Recharts, Framer Motion |
| الخادم الخلفي | Node.js, Express, Socket.IO |
| قواعد البيانات | SQLite للتطوير، PostgreSQL للإنتاج |
| الذكاء الاصطناعي | Python, scikit-learn, XGBoost, نماذج محفوظة |
| التخزين المؤقت | Redis مع بديل داخلي في الذاكرة |
| جمع البيانات | Puppeteer, Axios, Scrapers |
| الأمن | Helmet, CORS, Rate Limiting, Bearer Token |
| الاختبارات | Jest, Supertest, اختبارات Python |
| النشر | Docker, Docker Compose, Render, Kubernetes |

## 4. بنية المشروع

تم تنظيم المشروع بطريقة متعددة الطبقات، حيث تم فصل الواجهة الأمامية عن الخادم، وفصل منطق الأعمال عن طبقة البيانات. أهم المجلدات هي:

- `src/`: يحتوي على واجهة React والمكونات البصرية مثل لوحة التحكم، مركز المباريات، تتبع الأداء، وتحليل الذكاء الاصطناعي.
- `server.js`: نقطة تشغيل الخادم الخلفي المبني على Express.
- `routes/`: يحتوي على مسارات API مثل المباريات، التحليلات، Promosport، التعلم، والنظام.
- `services/`: يحتوي على خدمات منطق الأعمال مثل تحليل السوق، توليد التوقعات، إدارة المخاطر، التحديثات، والربط مع Telegram.
- `core/`: يحتوي على المكونات الأساسية مثل قاعدة البيانات، الأمن، Redis، محركات التوقع، والتنظيف.
- `models/`: يحتوي على نماذج الذكاء الاصطناعي المدربة.
- `scripts/`: يحتوي على سكربتات التدريب، الفحص، التحليل، الأرشفة، والتشغيل اليومي.
- `tests/` و`__tests__/`: يحتويان على اختبارات للتحقق من جودة النظام.
- `docker/` و`k8s/`: يحتويان على ملفات النشر والتشغيل داخل الحاويات.

## 5. طريقة عمل النظام

تبدأ دورة العمل بجمع بيانات المباريات من مصادر خارجية. يتم ذلك عبر خدمات Scraping تعتمد على Puppeteer وAxios. بعد الحصول على البيانات، تمر عبر مرحلة التحقق والتنظيف لتجنب الأخطاء أو البيانات الناقصة.

بعد ذلك يتم تحويل المعطيات إلى خصائص قابلة للتحليل، مثل:

- نتائج الفريق في آخر المباريات.
- قوة البطولة.
- الأداء داخل وخارج الميدان.
- المواجهات المباشرة.
- احتمالات الأهداف.
- تحركات الأسعار والرهانات.
- المعطيات التكتيكية والأخبار.

ثم ترسل هذه الخصائص إلى محركات التوقع، التي تستعمل نماذج تعلم آلي ونماذج تحليلية لإنتاج احتمالات وتوصيات. يتم تخزين النتائج في قاعدة البيانات وتخزينها مؤقتا في Redis لتقليل زمن الاستجابة. في النهاية، تعرض النتائج داخل واجهة React بطريقة منظمة.

## 6. الواجهة الأمامية

توفر الواجهة الأمامية تجربة تفاعلية للمستخدم. تحتوي على عدة مكونات، منها:

- لوحة تحكم رئيسية لعرض حالة النظام والتوقعات.
- مركز مباريات متقدم لعرض تفاصيل كل مباراة.
- مكونات خاصة بتحليل الأداء والدقة.
- صفحات لتحليل Promosport وتوليد التذاكر.
- لوحات خاصة بالسوق، القيمة المتوقعة، والرهانات ذات القيمة.
- واجهات لمتابعة التعلم والتحسين المستمر.

استعمال React وVite يسمح بتطوير سريع وأداء جيد، بينما تساعد مكتبات الرسوم البيانية مثل Recharts في تقديم البيانات بشكل بصري واضح.

## 7. الخادم الخلفي وواجهات API

يعتمد الخادم الخلفي على Express ويقدم عدة واجهات API. من أهمها:

- `/health`: للتحقق من صحة النظام.
- `/metrics`: لتصدير مؤشرات الأداء بصيغة Prometheus.
- `/api/promosport`: للحصول على توقعات Promosport.
- `/api/matches`: لإدارة بيانات المباريات.
- `/api/combos`: لتوليد وتحليل التذاكر المركبة.
- `/api/learn`: لتشغيل آليات التعلم والتحسين.
- `/api/system`: لمراقبة النظام والإعدادات.

كما يستخدم النظام Socket.IO لإرسال التحديثات الفورية إلى الواجهة دون الحاجة إلى تحديث الصفحة يدويا.

## 8. الذكاء الاصطناعي وتحليل البيانات

يمثل الذكاء الاصطناعي قلب المشروع. يعتمد النظام على نماذج محفوظة داخل مجلد `models/`، مثل النموذج الهجين `stitch_v24_hybrid.json` ونماذج أخرى مبنية باستعمال Python.

يقوم النظام بتحليل البيانات التاريخية والحالية لإنشاء توقعات مبنية على عدة عوامل. من أهم هذه العوامل:

- الأداء التاريخي للفرق.
- معدل تسجيل واستقبال الأهداف.
- قوة المنافسة.
- الأخبار والإصابات.
- احتمالات السوق.
- البيانات التكتيكية.
- نتائج المواجهات المباشرة.

كما يحتوي المشروع على سكربتات لإعادة التدريب والتعلم التكيفي، مما يسمح للنظام بتحسين نتائجه مع مرور الوقت.

## 9. قاعدة البيانات والتخزين المؤقت

يدعم المشروع SQLite في بيئة التطوير لأنها سهلة وسريعة ولا تحتاج إلى إعداد معقد. كما يدعم PostgreSQL في بيئة الإنتاج لأنه أقوى وأكثر ملاءمة للأنظمة متعددة المستخدمين.

يستعمل النظام Redis لتخزين النتائج مؤقتا وتحسين سرعة الاستجابة. وإذا لم يكن Redis متاحا، يستطيع النظام استعمال ذاكرة داخلية كحل بديل. هذه الآلية تجعل التطبيق أكثر مرونة وتحافظ على استمرارية الخدمة.

## 10. الأمن والحماية

يتضمن المشروع عدة آليات أمنية، مثل:

- استعمال Helmet لإضافة ترويسات HTTP آمنة.
- التحكم في CORS لمنع الوصول غير المرخص.
- تحديد عدد الطلبات عبر Rate Limiting.
- حماية بعض المسارات باستعمال Bearer Token.
- التحقق من المدخلات قبل معالجتها.
- استعمال Circuit Breakers لمنع انهيار النظام عند فشل خدمة خارجية.

هذه الإجراءات مهمة لأن المشروع يتعامل مع مصادر خارجية، قواعد بيانات، وواجهات API متعددة.

## 11. الاختبارات والجودة

يحتوي المشروع على اختبارات متعددة باستعمال Jest وSupertest، إضافة إلى اختبارات Python لبعض محركات التحليل. تغطي الاختبارات أجزاء مثل:

- الاتصال بقاعدة البيانات.
- خدمات Redis والتخزين المؤقت.
- محركات التوقع والقيمة.
- مسارات API.
- خدمات Scraping.
- أمن النظام.

وجود الاختبارات يساعد على اكتشاف الأخطاء مبكرا، خاصة لأن المشروع يحتوي على عدة خدمات مترابطة.

## 12. النشر والتشغيل

يمكن تشغيل المشروع محليا باستعمال:

```bash
npm run dev
```

كما يمكن بناء الواجهة وتشغيل الخادم في وضع الإنتاج. يدعم المشروع Docker وDocker Compose، ويحتوي أيضا على ملفات خاصة بالنشر في Kubernetes. هذا يجعله قابلا للتشغيل في بيئات مختلفة، من جهاز المطور إلى الخوادم السحابية.
